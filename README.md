# 忒修斯号 · Theseus Relay

> 每一句对话，都由一个全新的 Agent 接棒。它没读过历史——它只读上一棒留下的《工作简报》。

**中文** | [English](README.en.md)

界面看起来是连续的，但后台每个 Agent 只活一轮：读一份简报，做一组动作，写下新的简报就离场，下一棒带着它上场。它要验证的是**无状态工人 + 有状态协议**能不能成立——这是把「长会话」换成一棒接一棒的全部理由。

协议规范见 [docs/PROTOCOL.md](docs/PROTOCOL.md)，方向与阶梯见 [docs/ROADMAP.md](docs/ROADMAP.md)，验收脚本见 [TESTS.md](TESTS.md)。

## 当前状态

对话与工具两条路都已打通，`npm start` 即可跑：

- **一棒只做一件事**：要么发出一组互不依赖的工具调用，要么给出一则回答，两者不同时出现。判据是静态的——下一步是否依赖某个调用的返回值；依赖就交棒，不依赖就在本棒里发完。棒内没有「思考 → 操作 → 观察」的循环。
- **一条消息 = 一条链**：你的消息触发一整条棒链（工具返回会驱动新棒），直到给出回答或任务级预算触顶。上限 24 棒 / 每任务 $0.5，触顶按收尾退出并出报告，不抛错。
- **工具**：`search_files` / `read_file` / `write_file`，作用于会话工作区 `data/workspace/<sid>/`。路径守卫在脚本里，越界直接拒绝；每次写入逐笔记 `write_target`。
- **上下文恒定有界**：每棒输入 = 一份简报 + 一条驱动输入。工具输出超过 1000 字时全文落 `data/artifacts/<sid>/`，棒内只见摘要 + `->` 指针——所以「上下文有界」在工具棒上不失效。
- **简报五节**：进展 / 决策 / 用户画像 / 开放问题 / 副作用。累积压缩（不是本轮纪要）、决策只增不删、禁止占位符、有损预算 800 字（丢弃顺序：进展细节 < 开放问题 < 画像 < 决策）。
- **机械校验**：五项纯函数校验，不过则拒收重派一次，再不过走兜底摘要并标 `rejected`——校验器是棒级事务的 commit 条件。
- **翻日志**：完整 log 只对用户可见，Agent 默认不读，确有必要时按需检索（每棒最多 2 次）。
- **可审计换棒**：后台面板逐棒展示简报、它读到的完整输入、发出的调用与返回分类（确认型 / 信息型）、交接原因（`reply` / `info-return` / `ack-aggregate` / `budget`）、降级与抢救标记，以及成本双账本（接力实付 vs 同题单体模拟）。

`npm test` 74 项全绿（node:test，零依赖）。

## 要长成的两个形态

当前状态是这两条线的共同起点。它们共用同一份协议，区别只在「一根棒能干什么」和「一群棒怎么协作」。

**形态一 · 单棒链：每根棒都是可替换的工人。** 一根棒只读一份简报、发一组调用、写一份意图；真状态与长证据全部落在基底（盘上），简报退化成指针，于是「压缩时该丢什么」不再靠临场判断。审查由一根**从未看过写作过程**的棒承担——没有沉没成本、没有所有权偏见，这是单 Agent 架构造不出的审查者。确定性检查（测试 / lint / build）在前，LLM 审查在后。终点是每一步都可回溯，任何一根棒都能换成别的模型，由协议保证交接无损。

**形态二 · 任务板蜂巢：让任务自己滚动。** 真状态是一份任务板文档，每张卡带 `write_target`；一群棒按任务板并行推进，写目标互不相交由基底静态检查，阶段末由审查棒复核，异常与分派交给中间决策层（只判断有限选项、只返回概率分布；脚本能表达的规则不下放给它）。终局是一支自延续的蜂群：播一次目标，跑到 done；其中一类棒不产交付物，只优化分配规则与任务板／文档的结构，受三条护栏约束（协议不变量与校验器不可直接改、改进提案必须带前后度量、配额硬上限），KPI 直接取自成本账本与衰减度量。

设计纪律：① 任何新特性必须服务至少两条价值轨道，否则不做——六条轨道的定义与证明指标见 [docs/ROADMAP.md](docs/ROADMAP.md) §1；② 蜂巢隐喻只留在界面与文档里，不进 prompt——agent 之间传递的始终是普通简报。

## 与近亲架构的边界

它们都在解决同一件事——长会话随上下文填满而变贵、变蠢、忘事。区别在记忆载体与驱动信号：

| | 忒修斯号 | Ralph Loop | 单体长会话 / compaction |
|---|---|---|---|
| 驱动信号 | 任何输入事件 = 换棒（用户消息与工具返回同等） | 同一份 PROMPT.md 重复执行到 done | 上下文逼近上限（被动触发） |
| 记忆载体 | 简报（语言压缩物，有损，协议保证质量） | 磁盘（git / plan.md / 代码，无损） | 会话内摘要（隐式，质量无保证） |
| 信息丢失 | 显式：有损预算 + 丢弃优先级 | 隐式：假定磁盘无损 | 隐式：压缩是副作用 |
| 故障隔离 | 棒级（失败棒从未存在） | 迭代级（重来 + git 回滚） | 无 |
| 质量保障 | 机械校验器 + 确定性质量门 + 审查棒 | backpressure（测试 / 质量门） | 无 |
| 审查者 | 结构性无偏见（没看过写作过程） | 无独立审查者 | 无 |

从 Ralph 借走的是**纪律的安放位置**：规则放 harness 不放 prompt、状态放磁盘不放模型、失败模式全部可观测。两边剩下的分歧（状态落盘还是落在语言压缩物上）在基底化之后也已收敛。

## 运行

零依赖，Node ≥ 18：

```bash
npm start          # http://localhost:3000
```

### 配置 LLM（BYOK）

方式一：网页「设置」里填任意 OpenAI 兼容端点（DeepSeek / OpenAI / OpenRouter / Ollama…），Key 存浏览器本地。

方式二：站长内置通道——项目根放 `.env`（参考 `.env.example`），访问者无需配置即可体验。

### 本地联调（无 key）

```bash
npm run mock       # :5051 起一个 mock LLM
LLM_BASE_URL=http://localhost:5051 LLM_API_KEY=mock LLM_MODEL=mock npm start
```

## 架构

```
server.js          零依赖 HTTP 服务器（会话存储 + API）
src/task.js        单链步进 runner：一条用户消息跑完整条链，任务级预算与收尾
src/relay.js       单棒引擎：简报构建、翻日志检索、JSON 协议解析与抢救兜底
src/returns.js     返回值分类（确认型 / 信息型）与确认聚合
src/tools.js       最小工具集（search_files / read_file / write_file）+ 路径守卫
src/validate.js    基底校验器：五项机械校验，不过则拒收重派
src/pricing.js     模型价目与成本双账本：接力实付 vs 同题单体模拟
src/llmAdapter.js  OpenAI 兼容适配层（重试 + 超时）
public/index.html  聊天界面 + 后台接力实况面板
TESTS.md           协议一致性测试集（行为探针 + 真题四步脚本 + 自动化）
benchmark.html     配套智力测试（给人玩的，10 题自动判分）
```

## 实测沉淀的协议陷阱（详见 PROTOCOL.md §6、§8）

- 模型会把简报写成「本轮纪要」→ 协议必须强调累积压缩
- 模型会用「（保留旧结论）」占位符作弊 → 必须协议级禁止
- reply + 简报同在一个 JSON，长回答必撞 token 上限 → 需要截断抢救器
- token 压力下模型学会「稍后给你」式拖延 → 需要反拖延条款
