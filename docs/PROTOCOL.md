# 接力协议 · Relay Protocol v0.1

**中文** | [English](PROTOCOL.en.md)

> 忒修斯号的核心不是聊天界面，而是这份协议：**无状态工人 + 有状态协议**。任何模型、任何 runner，只要实现本协议即可接入接力系统。本文档是"从 chatbox 进化为 harness"的那条线头。

## 1. 参与者

| 角色 | 生命周期 | 看得见什么 |
|------|---------|-----------|
| **棒（Batons）** | 一次接棒即一生：产出「一组工具调用请求 + 一份简报」后即销毁 | ① 上一棒的《简报》 ② 本棒的驱动输入（用户消息 **或** 上一次工具调用的返回值） ③（受限）检索到的历史片段 |
| **基底（Substrate）** | 永生 | 全部历史 log、历代简报、任务板与检索索引 |
| **用户** | 上帝视角 | 完整 log + 后台面板（每棒输入/输出/检索行为全程可审计） |

**核心不变量：棒与棒之间唯一的传输介质是《简报》。** 简报丢失的信息就是真正丢失的信息——系统的所有工程努力都服务于让"该活的活下来，该死的痛快死"。

## 2. 回合契约（Turn Contract）

一个回合必须按序完成三件事，缺一不可：

```
1. READ   读入简报 + 本棒的驱动输入（此为该棒的全部世界）
2. ACT    发出一组工具调用请求 {"calls":[{tool,args},…]}，或对话场景退化为一则回答 {"reply":"…"}（v0.1 的受限检索 {"action":"read_log","query":"…"} 同属 calls 语义）
3. WRITE  输出更新后的简报：累积压缩 + 下一步意图，而非本轮纪要
```

传输格式为单个 JSON：工具棒用 `{"calls":[…], "handoff": "…"}`（见 §2.2），对话棒用 `{"reply": "...", "handoff": "..."}`。模型输出损坏时由基底负责抢救（见 §6），但对模型的合同要求始终是一次输出完整。

## 2.1 接棒的边界：信息驱动（2026-09-20 重写）

ACT 阶段的产出只有两样：**一组工具调用请求**和**一份简报**。同一根棒允许一次发射多个调用；是否在调用之间换棒，判据只有一条：

> **下一步的行动是否依赖某个工具调用的返回值。** 依赖 → 停在这里写简报并交棒，由新的一棒带着返回值上场；不依赖 → 这批调用在同一根棒里发完，不必为每个调用各开一棒。

这取代了 v0.1 的判据（"上下文有没有被清零重建"），并连带取消棒内 ReAct 循环——棒内不再有"思考 → 操作 → 观察"的多次往返。新判据不需要任何运行时度量：它是**静态**的，看一眼调用之间有没有依赖就知道该不该停。

**随之作废的一整套治理参数**（均为 v0.1 版）：棒内循环上限（6 次工具往返）、上下文预算（模型窗口 60%）、单棒墙钟（90 s）、死循环检测，以及"工作额度 + 收尾预留"的分段预算。棒内没有循环，就不需要这套必须靠实测标定的量。

### 返回值的两类处理

| 类型 | 例子 | 基底怎么处理 |
|------|------|-------------|
| **确认型** | 写入成功/失败、退出码、影响行数 | 聚合为一行写进下一棒的简报，例如「3 个写入：2 成功，1 EACCES」——**不为每个确认各开一棒** |
| **信息型** | 搜索命中、文件内容、报错详情 | 这就是"新信息"：触发换棒，下一棒带着它上场 |

### 由此而来的两条硬条款

1. **写目标声明**：每一次写入都必须有可识别的目标（由工具签名静态推出，或在任务卡上以 `write_target` 字段显式声明）。多棒并发时各棒的写目标必须互不相交，由基底**静态检查**，冲突检出即失败。这条检查是确定性的，**归脚本层**——不交给决策模型，更不交给生成式 LLM（位阶见 §7）。
2. **棒内仅存的环**：基底的校验重派（§4 / §6）是机械修补，不是 ReAct 循环，不受本节约束，但它仍然需要一个上限（见 ROADMAP §4 待修正）。

### 简报语义的迁移

当一根棒不再跨越工具调用时，它携带的就不再是"我这十几步做了什么"，而是**下一步要做什么、为什么、依据哪个证据**。简报由此从"历史压缩物"向**意图包（intent packet）**偏移：历史归任务板与基底，简报只留"指针 + 意图 + 决策账本"。§3 的四条不变量一条不改，反而更关键——**只存在于简报里的信息，换一次棒就没了。**

### 本节的演变

v0.1 的判据是「上下文是否清零」，允许棒内 ReAct 循环、靠上述四个参数兜底——那套承诺在 v0.1 里从未完整落地。改成静态的信息依赖判据之后，不是给那四个参数调优，而是从根上不再需要它们：这一类缺陷随之从代码里消失，而不是被修好。

## 2.2 工具棒契约（Tool-Baton Contract，H0）

工具棒是 §2 回合契约在任务场景下的具体形态。ACT 阶段的线格式：

```
{"calls":[{"tool":"search_files","args":{"dir":"docs","pattern":"预算"}}, …], "handoff":"…"}
```

一根棒一次动作：**要么发出一组调用，要么给出回答**，二者不同时出现。`calls` 与 `reply` 互斥——棒内没有"先调用、拿到结果、再回答"的往返。

### 最小工具集（H0）

| 工具 | 签名 | 返回类型 |
|------|------|---------|
| `search_files` | `{dir, pattern}`（子串匹配，大小写不敏感） | 信息型：命中行列表 |
| `read_file` | `{path, offset?, limit?}`（按行读，默认前 100 行） | 信息型：文件内容 |
| `write_file` | `{path, content}` | 确认型：成功/失败 |

路径一律相对于本会话的**工作区**（`data/workspace/<sid>/`），绝对路径与越界路径（`..`、盘符）由基底拒绝——路径守卫归脚本，不归提示词。

### 权限与副作用

- **权限按棒授予**：基底以白名单传入本棒可用工具（H0 默认三个全开）；越权调用不执行，返回一条拒绝确认（确认型，聚合进下一棒）。
- **写目标必须可识别**：`write_file` 的 `path` 就是 `write_target`，由工具签名静态推出，基底逐笔记账（§2.1 硬条款 1 的单链形态；并发不相交检查留待 H1）。
- **副作用账本**：简报第六节「副作用」，逐条列出本棒的不可逆操作，没有则写「无」。基底掌握的**实际**写入记录随返回值注入下一棒，与棒的自述互为对照。

### 长输出落基底（v0.3a）

工具输出超过阈值（当前 1000 字）时，基底把全文落盘为 artifact（`data/artifacts/<sid>/…`），棒内只见**摘要 + `->` 指针**。由此，"上下文有界"在工具棒上不失效：任何一棒的上下文里都找不到工具长输出的原文。指针有效性由 §4 校验器把守。需要细节的棒用 `read_file` 分段取回——取回动作本身又是一次信息型返回，照常换棒。

### 交接原因（可审计）

链上每一棒离场时，基底记录一个机械可判的交接原因：`reply`（给出回答，链终止）｜`info-return`（信息型返回驱动新棒）｜`ack-aggregate`（确认聚合交接）｜`budget`（任务级预算触顶收尾）。面板逐步显示 calls、返回分类与交接原因——这是 P3 审计在链上的落点。

## 3. 简报模式（Brief Schema）

六节固定结构，任何一代都必须完整输出：

```
## 进展        此前脉络的压缩 + 本代新进展
## 决策        已确定结论、被否方案及理由 —— 只增不删
## 约束        用户下达的、约束本会话行为的通用指令 —— 只增不删
## 用户画像    沟通风格、背景、在意什么 —— 合并更新
## 开放问题    已解决的清掉，新出现的加上（含下一步意图：做什么 + 依据哪个证据）
## 副作用      本棒的不可逆操作逐条列出；没有则写「无」（§2.2）
```

### 四条硬性不变量

1. **累积压缩**：简报 = 上一份简报中仍相关内容的压缩保留 + 本代新增。它永远不是"本轮纪要"。
2. **禁止元注释**：「（保留全部旧结论）」「同上」「略」是协议级违规——基底看不到旧简报原文，占位符等于销毁信息。决策与画像必须逐条完整写出，允许与上一份一字不差。
3. **有损预算**：总长硬上限（当前 800 字），丢弃优先级：`进展细节 < 开放问题 < 用户画像 < 决策与约束`。**决策是最神圣的一节**——它代表协议的免疫系统（防止后棒重提已否方案）。**约束与决策同等受机械保护**：§4 的「只增不删」diff 覆盖决策、约束、用户画像三节。
4. **落盘优先，指针可抛**：可抛弃性由「是否已落盘基底」决定，**不做临场判断**。已落盘的内容在简报中只留一行指针，压缩时随时可抛（基底可恢复，丢失无损）；未落盘的内容是唯一副本，必须留在简报里。由此 WRITE 动作隐含一条义务：**够重要的新决策/新约束，先落盘，再压缩。**

不变量 4 是简报从 prose 走向指针（ROADMAP v0.3）的桥：它把"压缩时什么该丢"从模型的临场判断（方差来源）变成一条可机械执行的规则——落盘了的随便丢，没落盘的绝不丢。

**意图包补充（2026-09-20）**：§2.1 之后，简报还要承载"尚未兑现的意图"——发出一组调用时返回值还没回来，此刻写下的必须是"接下来要做什么、依据什么"。意图本身不是决策，先写进「开放问题」；它一旦兑现并稳定下来，才升格进「决策」。

### 跨会话导入（v0.1.3）

简报链可整条导出（`{format:'theseus-brief-chain', v:1, exportedAt, batons:[{agentId,ts,handoff,handoffReason}], finalBrief}`），也可导入为新会话的初始简报。四条口径：

1. **只搬两节**：新会话的初始简报里，只有「决策」与「用户画像」来自上一会话；进展 / 约束 / 开放问题 / 副作用按简报规矩补齐，不搬旧内容。
2. **log 一行都不搬**：上一会话的 log 永不进入新会话（§5 的语义跨会话同样成立）。导入由基底清空目标会话的 log / batons / artifacts，agentCount 归零。
3. **导入简报就是"上一份简报"**：它必须能过 §4 的机械校验，且预算要留出余地——导入部分占满 800 字的话，第一棒要么丢条目、要么自己超标，两条路都以拒收收场。
4. **导入后的第一棒带硬规则**：导入简报自带 `【跨会话导入】` 标记，基底据此在 prompt 里加上"决策、约束与画像条目一条都不许少"——模型压缩条目会撞上第四条不变量（决策与约束只增不删）。

`format` / `v` 是 v0.5 schema 版本化的占位：导入端只认自己认识的 v，不认识的直接拒绝。

## 4. 基底校验（机械层）

提示词约束是第一道防线，不是唯一一道。基底在接收简报时执行机械校验，**不过则拒收**（走 §6 抢救管线重写）：

| 校验项 | 判定方式 |
|--------|---------|
| 六节齐全 | 标题结构匹配（进展 / 决策 / 约束 / 用户画像 / 开放问题 / 副作用） |
| 无占位符 | 元注释正则（「同上」「略」「保留旧结论」等模式） |
| 预算内 | 总字数 ≤ 当前上限 |
| 决策与约束只增不删 | 与上一份简报 diff：决策、约束、画像条目数不得减少 |
| 指针有效 | 不变量 4 产生的落盘指针，指向的基底路径必须真实存在 |

**已实现（v0.1.1）**：`src/validate.js` 把上表五项落为纯函数 `validateHandoff(brief, { prevHandoff, exists })`——除指针项外无 IO，返回 `{ ok, errors[], checks }`。两项口径在此定死：字数 = 去空白后字符数 ≤ 800；指针语法 = `-> 相对路径`（当前为条件校验：简报里没有指针就直接通过，等 v0.3 落盘规则落地后自动生效）。

原则：**能写进基底的规则，不留在提示词里。** 模型会作弊（§8 的实测陷阱都是模型作弊的实录），脚本不会。校验器同时是棒级事务的 commit 条件——校验不过的简报，如同没有产生过。**兜底生成的简报在开头自报来源**（`【简报来源·基底】`）：它没过校验却仍要交给下一棒（否则链路当场断掉），机械保证在这里退化为如实标注——下一棒与面板都有权知道这份简报不可靠。

### 基底诊断：召回抽查（v0.1.4）

长程衰减在这里第一次有了数字。探针每 10 棒跑一次，**它不是一根棒**：不产出简报、不推进棒号、不写 log，花费单独记账（不进棒级账本，否则 P1 的口径就掺了水）。

- 抽样与作答各一次调用：抽样只吃 **log 窗口**（不吃简报），产出的 ground truth 必须是 log 里的原片段；作答只喂 **当前简报**（不给 log，否则测的就不是简报的保留）。
- 判分机械化：数字与拉丁词一字不差必须出现；没有硬片段时，中文取每段的首尾 2-gram，命中任一即算答对。**判分不调用模型**，否则探针会变成自证。
- 归因分三类：事实在简报里 + 答对 = 保留成功；在简报里 + 答错 = **模型没用**；不在简报里 = **简报没写**。第三类顺带回查一次 log（§5 的检索），能检索到记「可救」、检索不到记「检索没给」——这第三列只作观察，不进百分比。
- 失败不藏：抽样失败记一条空率的记录，面板显示「—」，而不是悄悄跳过这次抽查。

## 5. 外部记忆检索（Log-as-Memory）

完整 log 永不自动进入任何棒的上下文。棒可通过翻日志动作按需检索：

- 每棒最多 2 次，每次最多 8 条命中（朴素 n-gram 打分即可，无需向量库）
- 检索结果以"系统注入"形式给出，并明确告知：*这只是片段，完整记录你依然看不到*
- 语义：**log 是档案库，不是工作记忆**。检索是探照灯，不是开灯

### 检索质量的三条口径（F1，2026-09-21）

命中不可信，失败就会多出一种「检索没给」——它和「简报没写」「模型没用」长得一模一样，衰减探针（v0.1.4）的判据会被它污染。三条都落在基底脚本里，不靠提示词：

1. **行抬头不参与打分**：命中行仍带 `【第N棒·用户】/【第N棒·助手】/【对照段·…】`（后棒需要知道这句话出自哪一棒），但打分只看抬头之后的正文——否则查「用户偏好」时「用户」二字命中几乎所有行，排序当场退化。
2. **低信息熵 token 过滤**：静态词表（中文功能词 + 抬头自身的词汇）与动态文档频率闸（token 在本次会话 log 中出现的行占比 ≥ 0.6 即视为无区分度）两级并用。任一级若把命中清空，就放宽到下一级重算，直至不过滤——过滤的目的是压掉噪声，不是删掉唯一线索，**宁可给出低质量命中，也不误杀真命中**。两处阈值在 `src/relay.js` 里是具名导出常量。
3. **结果去重**：按去抬头、空白折叠后的正文去重，同一句在多棒反复出现（用户复述 / 系统注入 / 模型自述）只保留最早一条；去重在截断到 8 条**之前**完成——额度是 8 条片段，不该被复述占满。

三条都是确定性计算：同一 (log, query) 连跑两次，返回逐字节相同。额度与语义不变（仍是每棒 2 次、每次 8 条）。

## 6. 故障语义（Failure Semantics）

| 故障 | 基底行为 |
|------|---------|
| JSON 损坏但 reply 字段可救 | 抢救正文，标记 `salvaged`，简报走独立摘要调用 |
| JSON 完全不可解析 | 整段输出视为 reply，简报走独立摘要调用 |
| reply + 简报超长截断 | maxTokens 上限需覆盖 reply+简报之和；截断由抢救器兜底 |
| 模型拖延（"稍后给你"） | 提示词级禁止：reply 与简报必须当轮完成 |
| 简报未过 §4 机械校验 | 拒收，标记 `rejected`，带校验错误重派一次；再不过则走独立摘要调用兜底 |
| 决策震荡（被否方案被后棒重提） | 基底比对决策账本历史即可检测：同一方案先否后提 → 告警，附上当初否决理由注入下一棒 |
| 棒整体失败 | 该棒从未存在——简报仍指向上一个成功棒，**棒级事务性天然成立** |

## 7. 决策层的位阶

棒与棒之间的高频判断（派几根棒、异常是重试还是转派、结果是否收齐）不需要生成文本。这一层夹在两个极端之间：

- **能写成确定性规则的，必须留在脚本**——例如各棒 `write_target` 是否相交（§2.1 硬条款 1）
- **真正的内容生成仍由 LLM 负责**
- 中间那段「有限选项 + 非确定性」的判断，由**只返回候选概率分布的决策类专用模型**承担，可以先用规则桩占位再替换

两条纪律：**它不得替代 §4 的基底校验器**（那是棒级事务的 commit 条件，必须永远是脚本）；**每一次决策的输出（含概率）必须落基底日志**——这使该层同时服务 P1 成本与 P3 审计两条轨道。

更远的推论：简报 schema 版本化之后，**棒可以跨模型、跨厂商接棒**（A 棒用便宜模型跑杂务，关键棒换强模型）——成本调度变成协议层的事。分阶段推进的过程见 ROADMAP 阶梯二。

## 8. 已知边界（诚实清单）

- 简报压缩方差大：不同棒对"什么重要"判断不同，长程信息衰减不可避免（这是特性，也是 bug）
- 跨会话导入只搬「决策 + 用户画像」两节，且受导入预算约束（超出时自尾部裁剪并如实标注）：简报链是有损记忆，不是全量备份
- 长程衰减**已有度量**（每 10 棒一次召回抽查，见 §4）：保留率与三类归因进面板，衰减不再是自白。度量本身是低保真的——判分只看关键片段，合理的改写可能被记成「模型没用」，这一偏差待实测标定
- 棒数与固定开销同步增长：粒度改为「一组互不依赖的调用 = 一棒」之后，同一个任务会拆出更多的棒，每根都要付一次「读简报 + 写简报」的固定开销。**纯对话场景的交叉点在 R3 / R4 之后重标为约 25 棒**（形状假定见 TESTS.md §D）；工具链场景的交叉点待 H1 之后重标。
- 中文 2-gram 检索是低保真方案，够 demo 但不够生产
- 每棒 2-3 次 LLM 调用（答 + 抢救兜底），成本高于单 Agent 连续对话——买的是有界上下文与审计性（v0.1.2 起这条不再是自白：面板实时给出同题单体的模拟花费，短会话确实更贵）。成本口径的两处偏差已修（2026-09-21）：换序后固定内容全部落在简报之前，端点回传的缓存命中按缓存价计费。
- 翻日志的"每棒 2 次"限额曾被模型误解为需用户批准——工具语义的提示词要写死
- 并行棒互不感知：各棒的写目标必须静态互不相交（§2.1），但"读到的世界已经过期"（另一根棒并发改了同一区域）这类竞态尚无协议级解法，留待 H1 实测
- **约束该不该跨会话搬运，未定**：导入只搬「决策 + 用户画像」，新会话的「约束」节是一句事实陈述。把约束纳入搬运是明显的下一步，但它会推高导入预算压力（导入上限 600 字），且"上一会话的上下文已经不在了，旧约束是否仍然成立"本身是语义问题，不是工程问题
- **第二条传输介质是个架构级问号**：要让约束根本不受压缩影响，就得由基底在简报之外单独维护一份约束登记表——顺带把"哪句话是约束"的识别也接过去（「约束」节的只增不删只覆盖"不许丢"，不覆盖"识别"）。这与 §1「棒与棒之间唯一的传输介质是《简报》」直接冲突，因此它不是可以顺手加上去的功能，而是一个需要先回答的问题
