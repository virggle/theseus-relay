# 多目的矩阵 · Purpose Matrix

**中文** | [English](PURPOSES.en.md)

> 忒修斯号的协议同时服务六条独立成立的价值轨道。本文定义每条轨道、它的证明指标与当前证据状态。多目的性不是六个功能，而是同一份协议的六种读法——「简报」既是成本控件，也是审计工件、事务日志与记忆载体。设计纪律：**任何新特性必须服务至少两条轨道，否则进 ROADMAP 的「不做什么」。**

## 1. 轨道总表

| 轨道 | 一句话主张 | 证明指标 | 当前状态 |
|---|---|---|---|
| **P1 成本** | 长会话输入成本有界，历史越长优势越大 | 成本双账本（ROADMAP v0.1.2） | 部分成立：长会话赢，短会话输 |
| **P2 稳定性** | 新鲜上下文：第 1 轮与第 N 轮同质量 | retention_rate（v0.1.4）+ 基准双轨（v0.1.6） | 假设，待证 |
| **P3 审计** | 每次换棒是人类可读、可复查的工件 | 实况面板（已实现）+ 每棒遥测（v0.1.2） | 已实现，遥测补强中 |
| **P4 事务性** | 失败棒从未存在；决策只增不删 | 校验器拒收与回滚事件（v0.1.1、v0.4） | 协议已定义，校验器待落地 |
| **P5 调度** | 每棒独立选模型，成本/能力按需配 | 路由表（v0.1.7）→ 跨模型接力（v0.5） | 远景，玩具版预演 |
| **P6 持久化** | 简报链 = 跨会话个人记忆 | 跨会话导入后的决策/画像保留率（v0.1.3） | 雏形（简报 schema），入口待建 |

轨道编号即引用符号：ROADMAP 每一级标注「服务轨道」，指向本表。

## 2. P1 成本——有界输入，且历史越长越便宜

**机制**：接力架构每轮输入恒定（一份简报 + 一条消息）；单体架构输入随历史线性增长。每棒的固定开销（简报再生的输出 token、抢救兜底调用）不随历史缩放——这是买有界性的价格。

**量化直觉**（按主流前沿模型价目、含 90% 前缀缓存命中估算）：成本交叉点约在万级 token 附近；此后优势单调扩大，历史越长差距越大。精确数字随价目表浮动，由 v0.1.2 的成本双账本实时给出，本文不锁死。

**适用场景**：长会话、本地小模型（无前缀缓存定价机制）、无缓存优惠的端点。

**诚实边界**：短会话（数千 token 级）接力不占优——固定开销还没被历史长度摊薄。双账本如实显示输赢；输了不藏着，是这条轨道的可信度来源。

## 3. P2 稳定性——对上下文腐烂的结构性防御

**问题**：长会话随上下文填满而变贵、变蠢、忘事（context rot）。注意力稀释是架构级现象；模型的隐式压缩（循环状态、内部记忆）也有自己的衰减曲线，只是不可观测。

**主张**：接力让每一棒都在新鲜上下文里工作——第 1 棒和第 500 棒的模型状态同构。协议压缩（简报）同样会衰减，但它是**可观测、可干预**的：衰减探针（v0.1.4）度量衰减，L2 装舱（v0.1.5）干预衰减。协议路线与模型隐式压缩的本质差异不是"不衰减"，而是**衰减可控**。

**证明**：基准双轨（v0.1.6）——同题双轨跑，量化"新鲜上下文在第 N 轮的质量优势"。

## 4. P3 审计——模型永远不会给你的东西

模型内部状态不可见、不可复查。忒修斯号把一切可审计物落在人类可读的基底上：简报链（每棒输入的完整快照）、翻日志行为、降级与抢救标记、遥测（v0.1.2 后含 token/延迟/模型维度）。换棒即检查点：任何一轮的决策都能回溯到当棒的完整输入——这不是日志分析，是协议保证。

## 5. P4 事务性——协议的免疫系统

失败棒从未存在（简报仍指向上一个成功棒，回滚即恢复）；决策账本只增不删，防止后棒重提已否方案。当前这些保证靠提示词自觉；v0.1.1 基底校验器把其中可机械化的部分变成脚本级确定性——校验不过的简报，如同没有产生过。v0.4 棒级事务补齐 commit/rollback 语义。

## 6. P5 调度——模型谱系分化是协议的红利

模型市场正在分化：有的 1M 窗口、有的 32K；有的便宜、有的强。对单体架构这是兼容性负担，对接力协议这是调度空间——杂务棒用便宜模型、关键棒换强模型（v0.5），带宽分级（v0.1.5）让同一份协议按接棒者配不同输入档位。v0.1.7 路由表是玩具版预演。

## 7. P6 持久化——模型吞不掉的动态记忆

前沿模型正在把静态知识查表、会话内状态、窗口内检索收回架构内部；但架构内记忆要么训练后写死（查表）、要么会话内有效（循环状态）。用户偏好、项目状态、跨会话决策是动态的，只能活在模型外部——简报链正是它的可迁移载体：人类可读、模型无关、可导出（v0.1.3）、可版本化（v0.5）。

## 8. 与模型架构演进的关系

对六轨道的影响不对称：

| 影响等级 | 轨道 | 原因 |
|---|---|---|
| 不受影响 | P3、P4、P6 | 审计、事务、动态记忆结构性活在模型外部 |
| 反而增值 | P2、P5 | 模型再强也吃不掉新鲜上下文的价值；谱系分化扩大调度空间 |
| 需重锚主张 | P1 | 从"省 token"重锚为"长会话有界"——见 §2 |

## 9. 设计纪律

1. 任何新特性必须服务 ≥2 条轨道，否则不做。例：带宽分级服务 P1/P2/P5，衰减探针服务 P2/P6
2. 每条轨道的证明指标必须落进面板或基准——可讲的故事不算数
3. 轨道冲突时，按「协议可靠性 > 可观测性 > 成本」排序取舍
