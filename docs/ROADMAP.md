# 方向 · 两个阶梯

**中文** | [English](ROADMAP.en.md)

> 忒修斯号的最终形态不是聊天框，而是一套**接力运行时**：无状态工人按协议接棒，在有状态的基底上完成长程任务。本文回答两件事——这份协议同时服务哪几条价值轨道（§1），以及它要经过哪几级长大（§2 单棒链，§3 蜂巢）。两个阶梯是同一份协议的两个成熟度轴：**阶梯一问「一根棒能干什么」，阶梯二问「一群棒怎么协作」**。README 里给的是两条轴的终态形态，具体路径在这里。每级都停在「最小可运行」。

## 1. 六条价值轨道

> 同一份协议的六种读法——「简报」既是成本控件，也是审计工件、事务日志与记忆载体。

| 轨道 | 一句话主张 | 证明指标 | 当前状态 |
|---|---|---|---|
| **P1 成本** | 长会话输入成本有界，历史越长优势越大 | 成本双账本 | 部分成立：长会话赢，短会话输 |
| **P2 稳定性** | 新鲜上下文：第 1 轮与第 N 轮同质量 | retention_rate + 基准双轨 | 假设，待证 |
| **P3 审计** | 每次换棒是人类可读、可复查的工件 | 实况面板 + 每棒遥测 | 已实现，遥测补强中 |
| **P4 事务性** | 失败棒从未存在；决策只增不删 | 校验器拒收与回滚事件 | 校验器已落地，棒级事务待做 |
| **P5 调度** | 每棒独立选模型，成本 / 能力按需配 | 路由表 → 跨模型接力 | 远景，玩具版预演 |
| **P6 持久化** | 简报链 = 跨会话个人记忆 | 跨会话导入后的决策 / 画像保留率 | 雏形，入口待建 |

轨道编号即引用符号：下文每一级都标注「服务轨道」，指向本表。

**设计纪律**（三条，适用于本文所有条目）：

1. 任何新特性必须服务 ≥2 条轨道，否则不做
2. 每条轨道的证明指标必须落进面板或基准——可讲的故事不算数
3. 轨道冲突时按「协议可靠性 > 可观测性 > 成本」排序取舍

### 各轨道要点

- **P1 成本**：接力每轮输入恒定（一份简报 + 一条驱动输入），单体随历史线性增长。每棒的固定开销（简报再生的输出 token、抢救兜底）不随历史缩放——这是买有界性的价格。**诚实边界**：短会话（数千 token 级）接力不占优，固定开销还没被历史长度摊薄；双账本如实显示输赢，输了不藏着。
- **P2 稳定性**：上下文腐烂（context rot）是架构级现象——注意力稀释，且模型的隐式压缩（循环状态、内部记忆）有自己的衰减曲线，只是不可观测。协议压缩同样会衰减，但它是可观测、可干预的：衰减探针度量衰减，L2 装舱干预衰减。**本质差异不是「不衰减」，而是「衰减可控」。**
- **P3 审计**：模型内部状态不可见、不可复查。忒修斯号把一切可审计物落在人类可读的基底上：简报链是每棒输入的完整快照。换棒即检查点——这不是日志分析，是协议保证。
- **P4 事务性**：失败棒从未存在（简报仍指向上一个成功棒，回滚即恢复）；决策账本只增不删，防止后棒重提已否方案。校验器把其中可机械化的部分变成脚本级确定性。
- **P5 调度**：模型市场正在分化——窗口大小、价格、能力各不相同。对单体架构这是兼容性负担，对接力协议这是调度空间。
- **P6 持久化**：用户偏好、项目状态、跨会话决策是动态的，只能活在模型外部；简报链正是一条可迁移的载体：人类可读、模型无关、可导出、可版本化。

**与模型架构演进的关系**（影响不对称）：P3 / P4 / P6 结构性活在模型外部，不受影响；P2 / P5 反而增值——模型再强也吃不掉新鲜上下文的价值，谱系分化只会扩大调度空间；P1 需要重锚——从「省 token」改为「长会话有界」。

## 2. 阶梯一 · 单棒链：一根棒能干什么

> 串行语义，每级停在「最小可运行」。

### v0.1 对话接力（已实现）

> 服务轨道：P1 成本 · P3 审计 · P4 事务

- 结构化简报 + 累积压缩 + 反占位符
- 翻日志（log-as-memory，按需检索）
- JSON 协议 + 截断抢救 + 反拖延
- 后台实况：每棒输入 / 输出 / 检索全程可审计

**已验证的性质**：上下文有界（成本恒定）、棒级故障隔离、身份连续性由协议保证。

### v0.1.1 基底校验器（已实现）

> 服务轨道：P4 事务性 · P3 审计

PROTOCOL §4 的五项机械校验落进代码：五节齐全、无占位符、预算内、决策只增不删、指针有效。不过则拒收重派（PROTOCOL §6）。

**为什么它排在工具棒前面**：反占位符、反拖延这些实测陷阱，此前全部靠提示词约束（模型自觉）。校验器是第一个「基底比模型可靠」的组件，成本极低（纯正则 + diff），却把简报质量从概率问题变成确定性问题——后续棒级事务、质量门、协议独立都建立在它的存在之上。

**落地情况**：`src/validate.js` 五项纯函数校验 → `relay.js` 拒收重派（每棒 1 次，仍不过则兜底摘要并标 `rejected`）→ 面板显示校验错误。

### v0.1.2 遥测与成本双账本（已实现）

> 服务轨道：P1 成本 · P3 审计

- 每棒遥测落会话存储：input / output tokens、latency、模型、翻日志次数、salvage / rejected 事件
- 面板新增**成本双账本**：同一会话累计两条曲线——实际接力成本 vs 模拟单体成本（按当前模型价目 × 全历史重读，含前缀缓存读价）
- 为什么它重要：P1 从论战变成面板上的实时数字。短会话输、长会话赢，都如实显示——输了不藏着，是这条轨道的可信度来源

**判断标准**：面板能实时回答「这个会话若走单体架构，到此刻已花费多少」。

### v0.1.3–v0.1.7 度量与多目的层（未做）

与工具棒无硬依赖，可交错推进；每项独立停在「最小可运行」。**这一层还是阶梯二 H3 自我改进蜂唯一的 KPI 来源**，别把它当成可有可无的装饰。

| 级 | 内容 | 判断标准 |
|---|---|---|
| v0.1.3 跨会话引导 | 新会话可导入上一会话终局简报的「决策 + 用户画像」两节作初始简报；面板可导出完整简报链 JSON | 关掉浏览器、开新会话导入后，模型能答对上一会话已定的决策 |
| v0.1.4 衰减探针 | 每 10 棒自动做一次召回抽查：从基底 log 抽 5 个事实问句独立作答，与原文比对，产出 `retention_rate` | 成为面板常驻指标，且能区分「简报没写」与「模型没用」两种失败 |
| v0.1.5 简报带宽分级 | 简报分三档：L0 = 400 字指针简报（小模型 / 杂务棒）、L1 = 800 字全简报（现行默认）、L2 = 简报 + 基底日志摘录包；按接棒者申报的窗口预算装舱 | 同一会话内不同棒按规则拿到不同档位，输出质量无感 |
| v0.1.6 基准双轨 | benchmark.html 新增协议基准模式：同题双轨跑（接力链 vs 单体长上下文），在第 30 / 60 / 90 轮插题，自动判分出曲线 | 一键产出双轨「质量-轮数」曲线 |
| v0.1.7 模型路由表（玩具版） | 设置页允许规则（含工具调用的棒用模型 X，纯对话棒用模型 Y）；面板显示每棒实际使用的模型 | 按规则混用两个模型跑完 50 棒会话，面板全程标注 |

> 服务轨道：v0.1.3 P6 · P5；v0.1.4 P2 · P6；v0.1.5 P1 · P2 · P5；v0.1.6 P2 · P1；v0.1.7 P5 · P1。

**两处顺序约束**：v0.1.5 的 L0 指针形态依赖落盘规则（在此之前 L0 退化为硬压缩档）；检索质量（F1，见 §4）须先于 v0.1.4 落地，否则衰减探针无法区分「检索没给」这类失败。

### v0.2 工具棒（= H0，已实现 2026-09-20）

> 服务轨道：P4 事务性（副作用账本）· P1 成本（任务级预算与震荡检测）· P2 稳定性（有界输入）

- ACT 阶段发出工具调用请求（文件读写、命令执行、搜索）
- 简报新增第五节**副作用账本**：本棒的不可逆操作逐条列出，下一棒接手前必须知道「世界上已经被改变了什么」
- 工具权限按棒授予（读写分离、危险操作白名单）
- **确定性质量门（backpressure）**：产物先过测试 / lint / build——零 token、零偏见、每次必跑；不过则当场重派，不进审查棒
- **棒级粒度**：取消棒内 ReAct 循环，改用 PROTOCOL §2.1 的静态判据——**下一步是否依赖某个调用的返回值**。原「循环预算」那一整套参数（6 次工具往返 / 60% 窗口 / 90 s / 死循环检测 / 收尾预留）**随之作废**。工具棒因此反而好写：不再需要一套必须实测标定的动态预算体系
- **写目标与写分区**：每次写入须带 `write_target`；多棒并发时各棒写目标必须互不相交，由基底静态检查（单链里没有并发写，不相交检查留待 H1）
- **任务级预算与震荡检测**：棒数上限、单任务成本上限（复用 v0.1.2 遥测）——注意它们是**任务级**的，不再按单棒计；决策震荡（被否方案被重提）由基底比对决策账本检测并告警（PROTOCOL §6）

**关键设计**：工具调用的证据落基底，工具调用的意图进简报。工人无状态，但世界有状态。

**判断标准**：一个 20 步任务全部跑完，全程无棒内循环，面板能逐步显示每棒的调用与接棒原因；且「证据落基底」必须可验证——工具长输出以「摘要 + 可取回引用」进入简报，全文只落基底，否则「上下文有界」在工具棒上立刻失效。

**落地情况**：单链步进 runner `src/task.js`（`runChain`，一条用户消息跑完整条链）+ 返回值分类与确认聚合 `src/returns.js` + 最小工具集 `src/tools.js`（search_files / read_file / write_file；路径守卫归脚本，写操作记录 target，权限白名单按棒授予）+ 简报扩五节（`src/validate.js`，副作用账本）。v0.3a 同步落地：长输出超 1000 字全文落 `data/artifacts/<sid>/`，棒内只见摘要 + `->` 指针；任务级预算 `maxBatonsPerTask=24` / `maxCostPerTaskUsd=0.5` 触顶停机出报告（基底生成、零 token），不抛错；面板逐棒显示 calls、返回分类（确认型 / 信息型）与交接原因（reply / info-return / ack-aggregate / budget）。`node --test` 51 项全绿；mock 无 key 联调（`MOCK_CHAIN=1`）跑通「写 + 搜 → 读 → 回答」三步链，实测驱动输入 517 字 vs 原文 5270 字。

### v0.3a 基底化 · 证据落盘与意图（H0 的前置，已实现）

> 服务轨道：P1 成本（长输出不进上下文）· P6 持久化（真状态落盘）

- **长工具输出落基底，简报只留「摘要 + 可取回引用」**——这是 H0 唯一强制的落盘能力。工具长输出一旦进简报，「上下文有界」当场失效
- 简报新增「下一步意图」（PROTOCOL §2.1 的意图包）：发出调用时返回值还没回来，此刻写下的是「接下来做什么、依据什么」
- 落盘规则沿用 PROTOCOL §3 不变量 4：已落盘的内容在简报里只留一行指针

**明确不做**：任务板、任务卡、`write_target` 静态不相交检查都不在本级——单链里没有并发写，不相交检查**没有检查对象**。它们属于 v0.3b / H1。

### v0.3b 基底化 · 任务板与指针简报（H1 的前置，未做）

> 服务轨道：P1 成本（简报变薄）· P6 持久化（真状态落盘、记忆分层）

- 简报从 prose 降级为指针：状态文件路径、任务列表 ID、SSOT 文档位置；字数上限随之下调（如 400 字）——越薄越稳，重建成本越低
- **任务板**：真状态的组织形式是任务板文档，每张任务卡含 `write_target`。它既是拼接工作的依据，也是「各棒写目标互不相交」静态检查的输入，还是 H3 自我改进蜂的优化对象
- **落盘规则即压缩规则**（PROTOCOL §3 不变量 4）：已落盘 → 留指针随时可抛；未落盘 → 唯一副本绝不丢。压缩时不做临场判断
- **记忆分层**：项目记忆落各自项目文件夹（SSOT 文档），跨项目可复用的知识沉淀为 skill 按需调用——项目间天然隔离，不占简报预算

**为什么排在 H1 而不是 H0**：单链的棒数只是线性增长，扇出才是乘性的。棒数涨到每任务几十根时，简报不降为指针式意图包，成本与延迟会双重爆炸。

### v0.4 审查棒与棒级事务（粒度改为阶段级，未做）

> 服务轨道：P4 事务性（棒级事务）· P2 稳定性（结构性无偏审查）

- **阶段级审查**：执行棒产出阶段成果后，由一根审查棒复核，而不是每根执行棒配一根。阶段粒度 = 让审查棒的输入保持有界的那个粒度
- 审查棒的结构性优势：**它真的没看过写作过程**——无沉没成本、无所有权偏见，这是单 Agent 架构造不出的审查者
- **分工原则**：确定性质量门拦得住的不交给审查棒——LLM 审查只做语义问题：命名、设计一致性、「做的是不是问的事」。便宜的确定性检查在前，贵的概率性审查在后
- 棒级事务：审查不通过 → 回滚到上一份简报重派，失败的棒不留痕迹

### v0.5 协议独立（未做）

> 服务轨道：P5 调度（跨模型接力）· P6 持久化（可迁移 schema）

- 简报 schema 版本化（`brief_schema: 1`），可校验、可迁移
- 棒实现与基底实现解耦：任何 runner（CLI、服务、别的 harness）实现同一份协议即可互接
- 终极形态：**跨模型接力**成为成本调度手段——杂务棒用便宜模型，关键棒换强模型，协议保证无损交接

## 3. 阶梯二 · 蜂巢：一群棒怎么协作（2026-09-20 起）

> 三条已拍板的规则 + 四段以 H 编号的里程碑。**本节取代 v0.2 及其后的排程方式**；旧条目的处置见本节的对照表。

### 根上的那一条：驱动信号换了

**旧：一条用户消息 = 一根棒。** 系统是被动的——用户不再说话，链路就停在那里。所以整个项目只能演示「聊天怎么换人」，接不上「任务怎么自己跑」，这就是它长期形同半吊子的原因。

**新：任何输入事件 = 一根棒，工具返回也算。** 系统第一次可以脱离用户自行滚动。协议侧的定义见 PROTOCOL §2.1。

### 规则一：粒度——一组互不依赖的调用 = 一棒

- 判据：**下一步的行动是否依赖某个工具调用的返回值**（PROTOCOL §2.1）。依赖就交棒，不依赖就在本棒发完
- 确认型返回（写入成功 / 失败、退出码、影响行数）由基底聚合为一行，**不为每个确认各开一棒**
- 每一次写入必须有可识别的 `write_target`；多棒并发时写目标互不相交，**静态检查，冲突即失败**——这条是确定性规则，归脚本层

### 规则二：审查粒度——阶段级，但阶段不许随缘定义

- 每个阶段产出后跟一根审查棒，不是每根执行棒都跟一根（太贵，且返工信号被绑得过细）
- **阶段粒度 = 让审查棒的输入保持有界的那个粒度**：产物清单能塞进一份简报 + 一个装舱预算。否则审查棒的输入会长成另一个长上下文，直接违反 P2 有界上下文

### 规则三：自我改进蜂（带护栏）

蜂群里有一类棒不产交付物，只优化「分配规则」与「任务板 / 文档系统的结构」；需要多少执行、多少审查、多少计划，配额由它自行分配。三条护栏：

1. **不可改区**：协议四条不变量（PROTOCOL §3）、基底校验器、棒级事务语义——不得直接改，只能提 ADR 由人确认
2. **改进提案必须带前后度量，无证据拒收**——把 §4 的校验思路上移到 meta 层
3. **配额硬上限**（建议先取总棒数的 10–15%，实测标定）——防止种群退化成「全是搞分配的蜂，没人干活」

它的 KPI 不新建：遥测与成本双账本（v0.1.2）+ 将来的 retention（v0.1.4）就是来源。**这也是它排在 H3 的原因：度量没落地之前，它只会空转。**

## 5. 不做什么

- 不做向量数据库：检索需求是「找回一句说过的话」，n-gram 够用，复杂度留给基底
- ~~不做多棒并行：接力是串行语义，并行是另一个协议的事~~ → **已解除（2026-09-20）**：并行是蜂巢的定义；写冲突改由各棒 `write_target` 互不相交的**静态检查**约束
- 不做流式输出：一次输出完整 JSON 是抢救器能工作的前提，宁可等待
- 不做提示词层的行为约束（能用基底校验器表达的）：规则放 harness 不放 prompt——模型会作弊，脚本不会
- **不让决策类模型替代基底校验器**：决策层只能承接「脚本表达不了的有限选项判断」，且输出必须落基底日志；棒级事务的 commit 条件永远是脚本
- 不为单一轨道加特例代码：任何新特性必须服务 ≥2 条轨道，单一轨道需求进 backlog 冷冻
